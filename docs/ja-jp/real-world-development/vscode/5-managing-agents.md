GitHub Copilot を agent mode で使うと、コードベースを探索し、変更を提案してファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、その作業をリアルタイムで確認できます。すべてのツール呼び出しやファイル編集を確認し、差分をインラインでレビューして、個々の変更を受け入れるか拒否できます。エディターを離れずに追加のプロンプトを送り、エージェントの作業を調整することもできます。

この演習では、次の操作を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして受け入れます。
- セッション中にエージェントへ指示し、ハイコントラストに加えてライトモードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼があり、既定のテーマが暗すぎると感じるユーザー向けにライトモードも必要になりました。新しい会話を始める代わりに、進行中のセッションに追加の指示を送ります。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各手順、探索したファイル、実行したコマンド、提案した編集が表示されます。ファイル編集は差分と **Keep** / **Undo** ボタンとともにインラインで表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りと編集、実行を求められたターミナルコマンドが表示されます。
3. ファイル編集が提案されたら、インラインに差分が表示されます。
   - **Keep** を選択すると変更を受け入れます。
   - **Undo** を選択すると変更を元に戻し、別の方法を試すようエージェントに指示します。
4. チャット上部の **Files changed** を開くと、セッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ターミナルコマンドの実行などに権限が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードを実装し終えるまで待ちます。完了すると、変更内容の最終的な要約が表示されます。

## エージェントにライトモードの追加を依頼する

ハイコントラストモードができたら、同じ会話でライトモードの切り替え機能も追加します。会話を続けることで、エージェントは先ほどの作業、変更したコンポーネント、スタイルの方針、local storage のパターンを引き続き利用できます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を確認し、ライトモードを追加します。
3. 新しい編集を確認し、ハイコントラストのときと同じように **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合（たとえば切り替え UI を意図せずリファクタリングする場合）、チャット入力欄の横にある **Stop** ボタンを選択し、意図を明確にする追加メッセージを送信します。

> [!TIP]
> 進行中のセッションに追加の指示を送ると、新しく始めるよりも早く作業できます。「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」「3つ目の切り替えを追加せず、既存の設定パネルにライトモードを加える」「両モードにキーボードショートカットも追加する」など、追加の指示で調整できます。

## 作業内容をレビューする

コミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストの更新が含まれます。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持など、アクセシビリティの方針を確認します。
4. 問題がなければ **Source Control** パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode で、進行中のセッションを監視して方向を示しました。ファイル編集を確認し、受け入れるか拒否し、コンテキストを保ったまま追加のプロンプトを送りました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を受け入れるか拒否しました。
- 追加のプロンプトで進行中のセッションを調整しました。

[次のレッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このラボを通してローカルのカスタムエージェントが作成した変更をレビューします。
